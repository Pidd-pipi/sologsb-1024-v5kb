# 光影谱 · 灯光演出提示设计台

面向灯光设计、编程与舞台监督的演出提示工作台。按场次维护通道、灯位、颜色、亮度、渐变、跟随关系和备注，并在拖动顺序后自动重算时间、提示通道或逻辑冲突。

## 功能

- 多方案数据模型；每个方案包含多个场次，每个场次包含完整灯光提示。
- 按场次维护灯位、控制通道、颜色、色值、亮度、渐入、保持、渐出、跟随目标、触发动作、备注和执行状态。
- 使用鼠标或键盘拖动提示排序；每次排序、参数应用或删除后自动重算全剧时间。
- 自动检测同通道叠光、跟随目标不存在或顺序异常、缺失通道/灯位、亮度越界、灯位重复等问题。
- 多个方案并排比较，按场次顺序显示提示时间、通道和亮度。
- 可冻结已确认场次；冻结后提示参数与排序只读，舞台监督或灯光设计可解除冻结。
- 未完成提示快捷跳转；`Alt+N` 可在所有未确认或存在阻断冲突的提示间循环移动。
- 角色权限：灯光设计可完整编辑，编程执行可调整参数，舞台监督可冻结场次，只读角色只能查看。
- 离线草稿自动写入 `localStorage`，模拟保存接口展示在线/离线同步状态。
- **执行对账**：把舞台监督从断网控台带回的 GO 记录按提示稳定编号接回计划，区分临时提前（GO 时间差）与参数改动（亮度、渐变等）。
  - 记录按稳定编号去重，重复导入只合并一次；同一提示出现两份不同记录时并列保留，等待舞台监督选定确认；确认前不改全剧时间。
  - 提示的编号、顺序或渐变时长（渐入/渐出）一变，未确认记录立即失效并可一键重算；已确认记录永久保留确认当时的计划快照，之后计划再变也只提示“已漂移”。
  - 冻结场次不能写入任何对账记录；编程执行只能导入或手动补录；确认与丢弃由舞台监督（及灯光设计）负责。
  - 合并在草稿上整体进行：任一条记录被拒（冻结、找不到场次/提示、数据非法）即整体放弃，恢复原方案与待处理清单，不产生半成品。
  - 支持从 JSON 文件导入 GO 记录，也可载入内置示例（含应成功与应被整体拒绝两份）。
  - 导出 JSON 同时带上执行记录、逐条差异、确认状态与确认快照；方案编排列表的提示编号旁用状态点标记待确认/失效/已确认。
- 最多 50 步撤销重做；快捷键包括 `↑/↓` 选择提示、`F` 冻结/解冻、`Ctrl/⌘+Z` 撤销、`Ctrl/⌘+Shift+Z` 重做、`Ctrl/⌘+S` 保存。
- 时间轴、提示列表、复选关系图和冲突面板均提供语义标签、焦点样式和读屏描述。
- 导出当前方案 JSON，便于制作交接与外部备份。

## 技术栈

- React + TypeScript
- Vite
- Chakra UI
- dnd-kit（鼠标与键盘排序）
- localStorage
- 无后端服务，全部数据在浏览器本地处理

## 本地开发

```bash
npm install
npm run dev
```

打开终端显示的 Vite 地址。源码没有硬编码宿主端口。

## 生产构建

```bash
npm install
npm run build
```

生产产物生成到 `dist/`。可用 `npm run preview` 预览。

## Docker

```bash
docker build -t sologsb-1024 .
docker run --rm -p 10024:80 sologsb-1024
```

容器内 nginx 监听 `80`，根据根端口表映射到宿主 `10024`。

## 数据说明

方案、提示、冻结状态、角色选择、执行对账条目和草稿都保存在当前浏览器。清除站点数据会删除本地设计稿，重要方案请导出 JSON 备份。

### GO 记录文件格式

导入文件为 JSON 数组，或 `{ "records": [...] }`：

```json
[
  {
    "id": "GO-0401",
    "planId": "plan-main",
    "sceneId": "scene-1",
    "cueNumber": "Q2",
    "firedAt": 9.5,
    "fadeIn": 8,
    "brightness": 80,
    "source": "断网控台 A",
    "firedBy": "programmer",
    "note": "月幕被临时提前"
  }
]
```

- `id` 是控台导出的稳定编号，重复导入同一编号只合并一次；`cueNumber` 是与计划配对的稳定编号。
- `firedAt` 为相对开演的实际 GO 秒数；`fadeIn/hold/fadeOut/brightness/colorHex` 可省略，省略即视为该项未改动。
- 缺编号、时间非法、找不到场次/提示、写入冻结场次都会导致整批拒绝并恢复原状。

## 校验

```bash
npm run verify
```

以 Node 断言覆盖：去重只合并一次、并列保留待确认、失效与重算、确认快照、冻结写入拒绝和合并失败整体回滚。
